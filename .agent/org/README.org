* Agent Org Workflow

ASP owns Org parsing, query, lint, capture, recall, and archive semantics.
Wendao is not an Org task read-model owner and must not regain an =orgize=
command surface.

** Tracking Surfaces

1. SDD files under =$PRJ_CACHE_HOME/agent/sdd/= own durable architecture
   direction.
2. ExecPlans under =$PRJ_CACHE_HOME/agent/execplans/= own detailed execution
   logs when a bounded slice needs them.
3. Org tasks under =$PRJ_CACHE_HOME/agent/org/= own task lifecycle, evidence,
   and recovery anchors.
4. Package docs own durable public behavior.

** Lifecycle

- =TODO= is planned but not started.
- =DOING= is active work.
- =DONE= requires validation evidence and an inactive =CLOSED:= timestamp.
- Archive operations are plan-first and must preserve ASP edit receipts.

** ASP Query Boundary

Find a task by remembered text:

#+begin_src sh
asp query playbook --documents org --kind task --term '<remembered text>'
#+end_src

Resolve a known Org section ID:

#+begin_src sh
asp query playbook --documents org --kind property --field key=ID --field value=<org-section-id>
#+end_src

Inspect SDD nodes:

#+begin_src sh
asp query playbook --documents org --kind property --field key=SDD_KIND
#+end_src

Validate Org syntax:

#+begin_src sh
asp org lint $PRJ_CACHE_HOME/agent/org
asp org lint $PRJ_CACHE_HOME/agent/sdd
asp org lint $PRJ_CACHE_HOME/agent/execplans
#+end_src

** Design Rule

Do not recreate =task-list=, =task-probe=, =task-recover=, =sdd=,
=agent-planning=, or =sparse-tree= as Wendao commands. Missing recovery
capabilities must first become parser-owned facts and reusable query/search
recipes in ASP.
