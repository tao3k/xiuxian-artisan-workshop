** Confirmed Audit Findings

- =xiuxian-db-store/src/valkey/client.rs::scan_keys= retains all matched keys
  until cursor zero, without a total request, key, byte, or deadline budget.
  =COUNT 256= is only a hint. The preceding Lean page-bound theorem modeled a
  stronger protocol than the server provides and has been removed.
- =ValkeyClient::run_command= retries every command after any Redis error.
  A lost response does not establish that a write was not applied. Replay
  safety must be explicit per operation before changing this shared behavior.
- =xiuxian-qianji-control::ValkeyHotStateStore= reads several mutable sources
  concurrently. Concurrency alone supplies no atomic snapshot guarantee.
  Consumer requirements must determine whether an observation interval or a
  coherent generation is required.

* Phase A: Explicit Scan Admission

Owner: =xiuxian-db-store=, with Qianji adapting the single current scan caller.

Introduce a scan policy with positive call and retained-data budgets and an
overall deadline. Preserve deduplication and cursor-zero completion. A page
larger than COUNT and an empty nonterminal page are valid protocol responses.
Represent budget exhaustion explicitly; partial evidence must never appear as
a complete empty result. A retained-data budget does not bound transport decode
allocation or server work: document and measure these separately.

Acceptance: adversarial reply fixtures exercise oversized and empty pages,
duplicates, nonterminating cursors, deadline expiry, and partial-result handling.
Lean models the same transition rules and each theorem maps to a Rust test.
Measure call count, retained bytes, allocations, and latency across keyspace sizes.

* Phase B: Observation Consistency

Owner: =xiuxian-qianji-control=.

Trace consumers before selecting consistency requirements. For telemetry, expose
the observation interval and incomplete components. If scheduling decisions
require a coherent generation, use a generation validation or atomic server
operation rather than treating a concurrent join as a transaction.

Acceptance: interleaved enqueue, lease transfer, expiry, and heartbeat removal
must not yield a falsely coherent observation. Benchmark any atomic operation's
server occupancy, payload size, and p95/p99 latency under concurrent writers.

* Phase C: Retry and Connection Ownership

Owner: =xiuxian-db-store=.

Classify read replay, idempotent write replay, and writes with ambiguous outcomes.
Inspect each command caller before replacing the generic retry loop. Reconnection
must not silently repeat a mutation or let an old failed connection invalidate a
newly installed connection. Keep transport failure distinct from execution outcome.

Acceptance: fault injection drops responses after server-side application;
non-idempotent effects occur at most once or return an explicit unknown outcome.
Concurrent reconnection fixtures test stale invalidation and shared recovery.

* Architecture and Cost Model

** Implementation Receipt

The first implementation supplies =ValkeyScanPolicy= with defaults of 1,024
logical calls, 100,000 distinct keys, 8 MiB retained key bytes, and a five-second
deadline. Read transport retries can double logical call submissions. Exhaustion
returns an error without partial success. Decode buffers and allocator overhead
are outside retained-byte accounting.

=HotStateSnapshot.atomic= defaults to false, including legacy deserialization.
The in-memory implementation sets it under its shared lock; Valkey leaves it
false and reports monotonic collection duration. The supplied =observed_at_ms=
remains the caller's expiry reference, not a server snapshot timestamp. Missing
payloads during concurrent mutation remain possible. Only completed collections
are returned; the observation is never a scheduling transaction.

Mutation commands now have one submission. A failed response is conservatively
reported as =OutcomeUnknown=, including decode errors. Callers must reconcile
effects before retrying. Read-only commands retry once on I/O errors. Connection
invalidation compares Arc instance identity under the lock; an old failed
request cannot remove a newer connection.

The same scan collector used by production has negative fixtures for oversized
pages, empty nonterminal pages, duplicate retention, budget exhaustion, and
deadlines. Duplex transport tests cover applied mutations with lost responses
and stale connection invalidation. These are deterministic local fixtures;
production server latency and interleaving stress measurements remain open.
